First things first ♥

I genuinely love turbopuffer

Let me say this plainly and happily right at the top: I love turbopuffer, I use it on many projects, large and small, and I recommend it for production. It’s an awesome piece of engineering, and I’m a huge fan.

blowfish isn’t here to pick a fight or run a race — it exists for the cozy side-quests where you want a self-hosted, open-source pufferfish swimming in your own aquarium.

Same API, zero lock-in: because the APIs match, moving between blowfish and turbopuffer.com is literally a base_url change.

Two minutes to first splash

Quickstart in two tiny steps

Boot blowfish locally, point the official turbopuffer SDK at http://127.0.0.1:8000, and run your first vector query.

1

Clone & boot blowfish locally

bash 
git clone https://github.com/endgame-labs/blowfish.git && cd blowfish
docker compose up --build --wait blowfish   # serves on 127.0.0.1:8000, auth off for local dev
now talk to it with the official SDK!
2

Upsert & query with the official turbopuffer SDK

python 
# pip install turbopuffer
import os
os.environ.pop("TURBOPUFFER_REGION", None)  # a region only applies to turbopuffer's own URLs
import turbopuffer
tpuf = turbopuffer.Turbopuffer(api_key="dev", base_url="http://127.0.0.1:8000")
ns = tpuf.namespace("hello")
ns.write(upsert_rows=[{"id": 1, "vector": [0.1, 0.2], "text": "hello, blowfish"}], distance_metric="cosine_distance")
print(ns.query(rank_by=("vector", "ANN", [0.1, 0.2]), top_k=1).rows)
What’s inside the shell

Small binary, big ocean energy

Six things clipped onto my sketchbook wall about how blowfish is built.

SDK-compatible

Speaks the turbopuffer API directly. Point any official client library’s base URL at blowfish — no wrappers, forks, or rewrites.

Python TypeScript Go Java Ruby Rust

Your bucket is the database

Stores everything in any S3-compatible bucket (AWS S3, Cloudflare R2, MinIO, or SeaweedFS) or a local directory. No other database. Servers are stateless caches — run more copies to scale out.

Vector, BM25, hybrid, & filters

Approximate nearest-neighbor (ANN) vector search, exact-matching BM25 full-text search, hybrid ranking, and metadata filters — all in one engine.

Scales to 100M on one machine

Handles 100M 1,024-dim documents on a single server, and a 10M load fits comfortably on a 4 GB machine. Plenty of room to grow before you even think about clustering.

Single Rust binary

One tidy, self-contained Rust binary with no external coordinator or companion database to wrangle. Drop it into Docker, CI, or an air-gapped server and go.

MIT licensed & readable

Open source under the permissive MIT license. Dive into the code to learn how object-storage search ticks. (Still pre-1.0 at v0.1.13, so storage formats may evolve!)

Lab notebook · Real measurements

Fast enough to be genuinely useful

No benchmark grandstanding here — just the actual numbers I scribbled down so you have a fair sense of how blowfish behaves at scale.

Not a race against anyone! Just honest field notes from a single box talking to S3.
100M documents

~0.1 s warm · ~1.2 s cold

  • Fully cold vector search: about 1.2 s (empty caches, everything pulled from S3)
  • Warm vector search: about 0.1 s (99.7 ms p50)
  • Quality & ingest: recall@10 0.954, loaded at 4,891 docs/s
10M documents

36.6 ms p50 warm · 533 ms cold

  • Cache-cold vector search: 533 ms p50
  • Warm vector search: 36.6 ms p50
  • Quality: recall@10 0.953
Modest hardware

10M load fits on a 4 GB machine

  • Your bucket holds the dataset, so the server stays lean and stateless
  • Great for smaller VMs, home labs, and cozy CI runners
BM25 · 1M passages

301 ms p50 cache-cold

  • Exact match: results match exact BM25 (overlap@10 1.000)
  • Full-text search right alongside your vectors and filters
Test rig details: Measured in the same AWS region as the bucket, on one c7gd.2xlarge (8 vCPU, 16 GB), with 1,024-dim embeddings.
